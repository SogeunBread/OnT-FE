# 미확정 사항

불명확한 요구사항과 임시 구현을 관리한다. 확정된 정책, 현재 코드의 동작,
남은 질문을 구분하고, 결정 후에는 결정 내용과 코드 반영 여부를 갱신한다.

## PT 일지 권한 — 2026-11-23

근거: 사용자가 제공한 `PT 일지 수정, 삭제 권한.png`.
아래 권한은 제공 자료를 기준으로 정리했다. 회원 수정 권한은 코드에 반영했고,
트레이너 생성·수정·삭제 화면과 취소·회차 처리는 후속 작업이다.

| 상태 | 트레이너 수정 | 트레이너 삭제 | 회원 수정 | 회원 삭제 |
| --- | --- | --- | --- | --- |
| 진행 전·진행 중 | 가능 | 가능 — 수업 취소 | 불가 | 불가 |
| 진행 완료·상호 동의 미완료 | 불가 | 가능 | 가능 — 시간 변경 불가 | 불가 |
| 진행 완료·상호 동의 완료 | 불가 | 불가 | 가능 — 시간 변경 불가 | 불가 |

- 생성은 트레이너만 가능하며 과거·현재·미래 날짜 모두 허용한다.
- 상호 동의 완료 자체는 회원의 기록 수정을 막는 조건이 아니다.
- 회원 수정은 명시적인 `status: "completed"`에서 허용한다. 상호 동의 여부는
  수정 권한에 영향을 주지 않는다. 수업 날짜·시작·종료 시각은 초안 변경과 저장에서 보호한다.
- `status`는 로컬 목업의 상태 계약이며 API 필드 명세를 확정한 것은 아니다.
  목업의 어제 PT는 완료, 오늘 PT는 예정 상태다. 시각 경과로 자동 변경하지 않는다.
- 회원 확인은 기존대로 예정 종료 시각 이후 허용하며 회차는 변경하지 않는다.
  완료 판정 정책이 정해지면 확인 가능 시점과도 일치시켜야 한다.
- 운동 수행 시간·휴식 시간은 기존 운동 편집 동작을 유지했다. 아래 질문이
  확정되면 해당 기록 항목의 수정 제한을 조정한다.

### 남은 질문

1. **진행 완료 판정:** 예정 종료 시각 경과로 자동 완료되는가,
   트레이너가 별도로 완료 처리하는가? 완료 확인 가능 시점도 이 기준을 따르는가?
2. **회원 수정 범위:** ‘시간 변경 불가’는 수업 날짜·시작·종료 시각을 뜻하는가?
   운동 기록의 수행 시간·휴식 시간은 수정 가능한가?
3. **완료 후 삭제 효과:** 상호 동의 전 트레이너가 삭제하면 예약과 회차도
   취소되는가? 한쪽만 동의한 경우 확인 상태는 어떻게 처리하는가?
4. **완료 확인 철회:** 회원·트레이너가 완료 확인을 취소할 수 있는가?
   현재 회원 확인은 되돌리기 기능이 없다.

## 운동·루틴의 임시 구현 — 확인 필요

아래는 명확한 합의 없이 구현한 동작이다. 확정 정책으로 간주하지 않는다.

| 항목 | 현재 구현 | 확인할 내용 |
| --- | --- | --- |
| 작성 중 루틴 불러오기 | 기존 운동 뒤에 추가, 중복 허용 | 추가·교체 방식과 중복 처리 |
| 루틴에서 새 일지 작성 | 루틴 이름을 제목으로 사용하고 기록값도 복사 | 제목과 세트·기록값 복사 범위 |
| 저장 조건 | 운동 1개 이상이면 빈 세트·0값 허용, 빈 숫자는 0으로 저장 | 최소 기록 조건과 빈 값 처리 |
| 일지 시간 | 종료 시각이 시작 시각보다 늦어야 함 | 같은 시각·자정을 넘기는 운동 허용 여부 |
| 새 일지 기본 시간 | 11:30~12:30 | 기본 시각과 운동 시간 |
| MY 운동 수정·삭제 | 기존 일지·루틴의 운동 스냅샷 유지 | 기존 기록에 변경을 전파할지 여부 |
| 작성 중 이탈 | 변경 시 확인 후 초안 삭제 | 임시 저장·복구 필요 여부 |
| 저장 후 이동 | 새 일지는 운동 목록, 루틴은 루틴함, 일지 수정은 상세 재열기 | 완료 후 복귀 경로 |
| 목록 정렬 | 개인 운동 다음 PT, 그룹별 시작 시각순 | 통합 시간순 등 정렬 기준 |
| 시간 선택 UI | 시·분 직접 입력 바텀시트 | 원하는 선택 방식 |

## 개발 단계의 제한

- API 연동 전 목업과 메모리 상태를 사용하므로 새로고침·앱 재실행 시 초기화된다.
  이는 영구 저장 정책을 확정한 것이 아니다.
- 회차 차감과 서버 권한 검증은 미구현이다. API 연동 시 명세 확인이 필요하다.
